# Privacy Policy

Codex Trajectory runs locally and reads Codex JSONL task logs from `CODEX_HOME/sessions` and, when requested for a target, `CODEX_HOME/archived_sessions`. Paginated targets may inherit earlier segments from either authorized root; copied parent context before a subagent's declared history boundary is excluded from that child trajectory.

To avoid rebuilding every full session overview during historical search, the plugin maintains `CODEX_HOME/codex-trajectory/session-search-index-v1.json`. This private derived index contains only hashed physical file identities, hashed lineage identities with file metadata signatures, and the bounded session ID, title, display-safe working directory, and model used by `list_codex_sessions`; it never contains transcript bodies, tool input or output, reasoning, Git metadata, or absolute task-log paths. It is limited to 10,000 entries and 8 MiB, is written atomically with mode 0600, refuses linked index files, and treats invalid or stale entries as cache misses. Any lineage-file change invalidates that session entry, and deleting the index is safe because it is rebuilt on demand.

The plugin does not edit task logs, persist a secondary copy of them, or add telemetry. Its Python runtime makes no application network requests unless the user explicitly enables the experimental CDP direct-stop integration; that integration uses only the configured loopback debugging port and rejects non-loopback debugger WebSocket URLs. The `uv` launcher may provision a compatible Python and, on Python 3.10–3.13, the pinned `zstandard` decoder according to the user's own uv configuration. The trajectory tools accept session identifiers rather than paths and use descriptor-checked reads to exclude descendant symlinks/reparse points, file hardlinks, non-regular sources, and files outside the configured roots. Compressed rollouts are decompressed locally into a bounded spool and are never uploaded. Safe summary mode is the default: tool inputs, tool outputs, raw record metadata, absolute log paths, Git remotes, base instructions, and encrypted reasoning are not returned. Full-detail mode requires an explicit tool parameter or confirmation in the viewer; it returns bounded tool inputs and outputs but still excludes base instructions and encrypted reasoning. All returned collections and text fields are bounded.

The CDP integration is off by default. Its app-only setter stores the enabled flag and loopback debugging port in a private plugin-owned file under `CODEX_HOME/codex-trajectory`; a second bounded heartbeat stores process/runtime booleans, a timestamp, and only a fixed public error category. Settings, heartbeat, control-lock, and watcher-lock reads accept only bounded single-link regular files and reject symbolic links, hardlinks, non-regular files, and oversized content. A cross-process lock serializes recovery and replacement, and settings revisions prevent an older process from restoring a later-disabled or changed port. Disabled status reads do not probe the configured port. Direct CDP discovery does not follow redirects, applies one absolute operation budget, and rejects non-loopback or cross-port WebSocket URLs.

On macOS and Windows, the token-bearing Codex in-app Browser shortcut is available only when operating-system TCP ownership checks bind the exact CDP connection to the authenticated Codex desktop host. The watcher keeps an opaque host identity containing a PID, process start identity, executable path, and—on Windows—the Codex package family. It sends that identity only between local plugin processes, rejects PID reuse and ambiguous TCP ownership, validates each connection before its WebSocket handshake can carry the local viewer URL/token, and stops serving when the host exits. macOS also validates the Codex application signature; Windows requires the authenticated Codex package family throughout the accepted process ancestry. Authentication failures and unsupported platforms never send the viewer URL/token or create token-bearing injection. The remaining direct-stop channel sends only bounded task/turn identifiers and a fixed App Server action sequence to the explicitly configured endpoint; users must therefore treat that endpoint as trusted.

After user review, an asynchronous session-start hook may read the same bounded private setting and authenticated host identity early enough to restore an already enabled watcher. On Windows, uv's windowless launcher keeps that watcher in the session-bound hook process rather than creating a visible console or relying on a nested process to escape the Codex Job Object. The hook produces no trajectory output, adds no telemetry, carries no viewer token, and does nothing when the opt-in is disabled or the host cannot be authenticated. MCP startup remains a fallback.

The optional one-click stop control and user-armed quota guard use only the explicitly enabled local direct-stop path. The standard side panel invokes the app-private MCP action to pause an active Goal and interrupt the bound App Server turn. It accepts only validated identifiers, `manual`/`auto` source, integer threshold, and locale; it rejects extra fields and arbitrary prompt text. It does not invoke the model, post a task or follow-up message, enter the steering queue, delete or clean worktrees, kill unrelated operating-system processes, or read/change composer drafts and attachments. When direct CDP is unavailable, the controls fail closed instead of substituting a model-mediated message. The guard defaults to off; its threshold, enabled state, and one-shot quota-cycle latch are stored through the host's widget-state facility when available.

When a user invokes the plugin through Codex, structured results may become part of the active Codex conversation and may therefore be processed according to the user's Codex service configuration. Users should review task contents before enabling full details.

The project operates no remote service and receives none of this local data. The derived search index can be deleted locally at any time and will be rebuilt on demand. Security-sensitive reports should follow [SECURITY.md](SECURITY.md).
