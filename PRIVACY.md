# Privacy Policy

Codex Trajectory runs locally and reads Codex JSONL task logs from `CODEX_HOME/sessions` and, when requested for a target, `CODEX_HOME/archived_sessions`. Paginated targets may inherit earlier segments from either authorized root; copied parent context before a subagent's declared history boundary is excluded from that child trajectory.

To avoid rebuilding every full session overview during historical search, the plugin maintains `CODEX_HOME/codex-trajectory/session-search-index-v1.json`. This private derived index contains only hashed physical file identities, hashed lineage identities with file metadata signatures, and the bounded session ID, title, display-safe working directory, and model used by `list_codex_sessions`; the title is a potentially sensitive excerpt of the first prompt (up to 100 characters), while no additional transcript bodies, tool input or output, reasoning, Git metadata, or absolute task-log paths are persisted. It is limited to 10,000 entries and 8 MiB, is merged under a cross-process lock and written atomically with mode 0600, refuses linked index files, and treats invalid or stale entries as cache misses. Any lineage-file change invalidates that session entry, and deleting the index is safe because it is rebuilt on demand.

The plugin does not edit task logs, persist a secondary copy of them, or add telemetry. Its Python runtime makes no application network requests. The UI uses the native MCP Apps host without a separate HTTP server. The `uv` launcher may provision a compatible Python and, on Python 3.10–3.13, the pinned `zstandard` decoder according to the user's own uv configuration. The trajectory tools accept session identifiers rather than paths and use descriptor-checked reads to exclude descendant symlinks/reparse points, file hardlinks, non-regular sources, and files outside the configured roots. Compressed rollouts are decompressed locally into a bounded spool and are never uploaded. Safe summary mode is the default: tool inputs, tool outputs, raw record metadata, absolute log paths, Git remotes, base instructions, and encrypted reasoning are not returned. Full-detail mode requires an explicit session ID plus the full-detail parameter or confirmation in the viewer; it returns bounded tool inputs and outputs but still excludes base instructions and encrypted reasoning. All returned collections and text fields are bounded. The default target is the latest modified active session, not caller identity; archives are opt-in. `list_codex_sessions` does not modify source logs but updates its private derived index (its MCP read-only hint is therefore false). The native panel receives the calling task identifier on each tool request and does not persist that identifier separately. Missing or invalid native context requires explicit task selection. MCP startup only prewarms bounded read-only caches; it starts no watcher and registers no lifecycle command hook. The plugin has no task interruption, Goal mutation, automatic stop, composer, or follow-up-message feature.

When a user invokes the plugin through Codex, structured results may become part of the active Codex conversation and may therefore be processed according to the user's Codex service configuration. Users should review task contents before enabling full details.

The full-detail confirmation explicitly offers a checked **Default to full details for all tasks on this device** option. Continuing with that option saves consent for subsequent task selections and reopened panels; unchecking it loads full details for the current panel only. The app-only preference tools read and atomically save `CODEX_HOME/codex-trajectory/viewer-preferences-v1.json`, containing only a schema version and the boolean `defaultFullDetails`, with mode 0600. No task identity or content is stored there. Missing, malformed, oversized, unreadable, or linked settings default to summaries, and failed saves are reported in the viewer. **Restore safe summary default** revokes the preference. Public trajectory tool defaults and live views remain summaries; the viewer uses the saved choice to allow on-demand full-detail requests after a record click. Opening, refresh, switching tasks, and earlier-history reads remain summaries. First confirmation requests the currently inspected record; each detail read returns at most 50 records, held in a bounded panel cache that is invalidated on refresh, task changes, revocation, or teardown.

Canonical command records may expose fixed allowlisted activity labels, such as reading files or running tests, plus a valid recorded integer exit code in their safe summary. These labels are derived locally from bounded command metadata without executing it. Argument values, file paths, search patterns, script bodies, and command output are not included in the activity description. Unknown or ambiguous commands use a fixed fallback; inspecting their original command and output still requires full details.

Tasks exceeding the default 512 MiB read budget report their size without exposing log paths. Users can explicitly choose a larger byte budget up to 64 GB for the selected task; the panel holds that choice only in memory and sends it on that task's read requests. It does not persist a new setting or raise another task's budget. Per-line, page, cache, discovery, and filesystem bounds remain independent, and enabling a larger budget does not enable full details. Compressed tasks may use temporary disk space up to the selected decompression budget.

The project operates no remote service and receives none of this local data. The derived search index can be deleted locally at any time and will be rebuilt on demand. Security-sensitive reports should follow [SECURITY.md](SECURITY.md).

Safe-summary pagination also uses an ephemeral SQLite index in a private OS temporary directory. It contains bounded safe record and turn summaries, aggregate statistics, and internal source paths and validated byte positions; paths are never returned by the index. It does not store tool inputs, tool outputs, raw record metadata, base instructions, or encrypted reasoning. A task index is capped at 128 MiB, with at most four indexes / 256 MiB per process, and is removed on eviction or normal process exit. An abruptly terminated process may leave a temporary directory, which can be deleted safely. Every lineage file's signature and the selected read budget participate in invalidation. Full-detail reads reopen the original log through the existing filesystem checks and load only selected records' associated source lines; compressed segments require a bounded decompression spool.

Live quota polling also reads bounded tails from up to 32 recent active local plain rollouts, independently of the displayed task. Each read is at most 256 KiB; only complete quota event lines of at most 64 KiB are decoded. Compressed and archived logs are excluded from this account-sample lookup. The bounded process cache retains only descriptor-checked file signatures, normalized Codex window percentages/durations/reset times, and sample times. It persists no quota cache, excludes inference-reserve buckets and credit/account/plan fields, makes no account API request, and returns no other task content or identity. Local logs can retain samples from an earlier account; the plugin cannot verify current account identity or activity on another device. The tooltip identifies this as a local log sample rather than an authenticated live account value.
