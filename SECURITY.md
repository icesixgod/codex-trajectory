# Security Policy

## Supported versions

Security fixes are provided for the latest released version.

## Reporting a vulnerability

Do not open a public issue for a vulnerability that may expose local task content or escape the authorized Codex session directories. Use GitHub's private vulnerability reporting for this repository. Include the affected version, platform, reproduction steps, and expected impact. You should receive an acknowledgement within seven days.

## Security model

All user-facing trajectory and app-only live-update tools are read-only and accept session identifiers rather than file paths. They resolve each configured root, then discover only regular, single-link descendant files below the active or archived root; descendant symbolic links, file hardlinks, root escapes, ambiguous ID prefixes, and inconsistent paginated lineage boundaries fail closed. Session and JSON-RPC inputs have byte, collection, nesting, and numeric conversion bounds, and public filesystem failures do not include local paths. Two local actions are app-private and hidden from the model: the setting tool writes atomic mode-0600 CDP settings/heartbeat files below the plugin-owned `CODEX_HOME/codex-trajectory` directory, while the stop tool can pause the exact bounded task's active Goal and interrupt its active turn only after the persisted CDP opt-in is enabled. Neither writes task history; the setting path refuses symbolic-link destinations.

Safe summary mode excludes raw inputs, outputs, metadata, base instructions, and encrypted reasoning. Full details remain bounded and still exclude base instructions and encrypted reasoning, but the plugin cannot protect content after a user explicitly loads those details into a Codex conversation. The viewer uses a restrictive Content Security Policy, escapes log-derived markup, and times out unanswered host requests.

The experimental CDP injector is disabled by default, allows only loopback HTTP/WebSocket endpoints, refuses HTTP redirects during discovery, bounds HTTP/WebSocket messages and target counts, and applies an absolute deadline to each WebSocket command. It evaluates the token-bearing injector only in Codex-owned `app://` renderers, removes stale injection state from other targets, and tries every eligible renderer before reporting that the bridge is unavailable. Its settings, heartbeat, and process-lock reads reject symbolic links, hardlinks, non-regular files, and oversized content; runtime replacement asks the verified old watcher to exit through its private setting instead of signaling a possibly reused PID. Its separate local viewer binds an ephemeral `127.0.0.1` port, requires a random in-memory 256-bit path token and exact loopback Host header, disables caching, and applies restrictive parent/viewer Content Security Policies. The Browser tool bridge accepts at most 64 KiB of interoperable JSON per call and allowlists only trajectory reads/updates plus the plugin-owned CDP setting/status tools; the viewer defaults to safe summary and requires explicit confirmation for bounded full details. Its read-only theme route returns an exact key set of bounded CSS colors from a fixed Codex-property allowlist, accepts no caller-supplied selector or property name, and rejects non-color values before they reach the viewer. A separate read-only task-state route requires an exact bounded session identifier and returns only a boolean plus a bounded turn identifier or null. Both the Browser stop route and the app-private direct-stop tool reject arbitrary prompts and accept only bounded identifiers, a fixed source enum, integer threshold, and locale; the private tool permits an omitted turn candidate only so it can bind the current active turn itself. They pause an active Goal before calling `turn/interrupt`, rebind a rejected stale turn at most once, and never read or write composer content or attachments. The standard Apps component does not fall back to `sendFollowUpMessage`; disconnected controls fail closed. CDP itself grants broad control over the application renderer to any local process that can reach the debugging port; users must never bind or forward that port beyond loopback. Codex DOM or App Server bridge changes can break the integration, but unmatched pages remain unchanged and disabling the feature removes its node, closes the viewer server, and stops its watcher.
