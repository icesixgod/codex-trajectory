# Codex Trajectory plugin

This directory is the installable Codex plugin. Repository-level installation, privacy, interface, development, and attribution documentation lives in the [project README](../../README.md).

The MCP runtime reads only authorized local Codex session roots, validates legacy and paginated rollout lineages, excludes linked files and inherited subagent prefixes, and defaults to safe summaries. Use the plugin through its bundled Skill or the `list_codex_sessions`, `get_codex_trajectory`, and `show_codex_trajectory` tools. The viewer also has an adaptive live window backed by an app-only safe-summary update tool: Codex gets a full-height side panel with frozen task totals, a remaining-quota badge, one-click and optional threshold stop controls, and a scrolling per-record Token stream, while regular Chromium pages can use native video PiP. Stop controls require the experimental loopback CDP opt-in. The standard Apps surface calls an app-private, model-hidden stop tool; the configured Browser uses its session-bound endpoint. Both pause an active Goal and interrupt the active App Server turn directly without posting a follow-up message, invoking the model, opening the confirmation dialog, entering the steering queue, or touching composer drafts and attachments. Manual Stop rearms for a later running turn, while automatic Stop stays latched across later turns in the same quota cycle; stale turns rebind once and transient failures retry. When direct CDP is unavailable or a different trajectory is selected, the controls fail closed. The same setting runs a loopback-only watcher that injects **View trajectory** after `Full access`; it opens the complete safe-summary-first interface as a tokenized Codex in-app Browser tab without covering Environment/Changes. Each updated MCP runtime reconciles the opt-in and safely replaces a verified older watcher. Public trajectory tools remain read-only; private local actions are constrained to plugin-owned CDP settings or the exact bounded task stop. Protocol, projection, privacy, and resource limits are documented in the [interface reference](../../docs/interface.md).
